# Adding a cross-language construct (operator / mark / builder method)

A new thing that crosses the Python↔JS bridge as serialized IR touches **more files than just the schema**; missing one fails late (at parity-render or CI, not at JS build), so do all of these in one pass rather than discovering them a failure at a time:

1. **JS factory** — author it under `packages/gofish-graphics/src/ast/` and export from `src/lib.ts`. Tag it with `__serialize = { type, opts }` so it round-trips (`createMark`'s and `createOperator`'s `serialize` config does this). Record the options as the caller passed them: the emitter (`toJSON`) keeps only the keys the construct's descriptor declares (step 3), plus `debug`, and drops function values, so a field missing from the descriptor never reaches the wire.
2. **JS reconstruction — one table line.** Add the factory to `FACTORIES` in `packages/gofish-graphics/src/serialize/registry.ts`, keyed by the wire type. The descriptor's kind picks the call: `factory(opts)` for an operator or leaf mark, `factory(opts, children)` for a combinator mark, so a dual-form construct has one line. Only an operator whose IR is not its factory's options object (`derive`, `resolve`, `join`, `log`, `filter`) gets a hand-written builder in `OPERATOR_BUILDERS`, and a construct that needs recursive reconstruction (like `cut` or `offset`) gets its branch in `fromJSON.ts`'s `mapMark`. `pnpm --filter gofish-graphics test:serialize` fails if a descriptor has no factory or a factory has no descriptor. Both hosts of Python IR render through this one deserializer (`Serialize.renderIR` in `fromJSON.ts`): the notebook widget (`packages/gofish-python/widget-src/index.ts`) and the parity render harness (`tests/harness/main.ts`, which only adds an HTTP `DeriveBridge`).
3. **One descriptor entry** in `packages/gofish-ir/src/frontend/descriptors.ts` — the single-source table of a construct's fields (operators, leaf marks, combinator marks, coord transforms), in the small `t.*`/`ch.*` type DSL. This is what `validate.ts` (generic interpreter over the table — operators reject on an unknown/mistyped field, leaf marks only warn during the current rollout), `jsonSchema.ts` (per-construct `$defs`, generated at call time), and the Python factory (next step) all read off. A nested option object a field takes (like `axes`) is declared by name in `OPTION_TYPES` and referenced with `t.ref(name)`; the validator, the JSON Schema, and the Python generator (which renames its keys to snake_case and rejects unknown ones) all read it there, and the generator fails on a `t.ref` it does not know. Envelope/structural types (`ChartIR`/`LayerIR`/`DataIR`/`MarkIR` union, `ChannelValue`, `ConstraintIR`, `LabelIR`, `TranslateIR`) and `cut`/`offset`/`ref` are NOT in the table — those stay hand-authored directly in `schema.ts`/`jsonSchema.ts`, since they're recursive/structural shapes rather than flat field bags. After adding an entry: `pnpm --filter gofish-ir build` and `pnpm --filter docs sync-ir-schema` (CI runs `check-ir-schema`).
4. **Python wrapper — run the generator, don't hand-write the factory.** `pnpm --filter gofish-python gen` regenerates `packages/gofish-python/gofish/_generated.py` from the same descriptor table (closed-signature leaf marks, combinator-only marks incl. the compositing `pyName` renames, `_opts()` cores for dual-form constructs) and is CI-checked for freshness — do not hand-edit `_generated.py`. Hand-written Python work in `gofish/ast.py` is now only needed for genuinely non-mechanical constructs: the operator-vs-combinator dispatch that calls into a generated `_opts()` core, and anything not in the descriptor table at all (`derive`/`resolve`/`join`'s bridge logic, `field`/`datum`/`normalize`/`repeat`/`ref`/`select_all`). Add the `__init__.py` export either way. A **strategy** (one choice from a set, e.g. `Overlap.separate()`, `Curve.monotone()`) is never a top-level export: it goes in its family's module in both languages (`src/families/<family>.ts`, bound in `lib.ts` with `export * as`, plus a `package.json` `exports` subpath; `gofish/<family>.py`, bound in `__init__.py` with `from . import <family> as <Family>`). See #1013. A strategy that crosses the wire (Tile, Overlap, Curve) is one plain object `{ kind, ...params }` in JS and on the wire: declare its kind and params (types, bounds, defaults, docs) once in `STRATEGIES` in `descriptors.ts`, add it to the family's IR type in `schema.ts` (`descriptors.test.ts` checks they agree), write the JS factory, and run the generator, which writes `gofish/<family>.py` (do not hand-edit it). The option that takes the family is `t.ref("<Family>")`, and the JS layout checks the value with `Frontend.checkStrategy` where it reads it (#1011). Python names are snake_case: the generator derives each kwarg with `pyKwarg` (`strokeWidth` → `stroke_width=`) and maps it back to the camelCase wire key, and appends `_` to a Python keyword (`from` → `from_=`), so there is nothing to declare for either. Hand-written Python functions and methods are snake_case too. The parity derive server (`tests/scripts/derive-server.py`) returns a story builder's own `to_ir()` with only its rows inlined, so a new construct needs nothing there, unless it introduces a new kind of Python callback, which `ir_of` must register.
5. **Parity stories** — port pure-spec stories to `tests/python-stories/`; add genuinely non-portable ones (e.g. a JS-side function-mark composing refs, which can't cross the derive RPC) to `tests/.python-sync-exempt`. Gates, and what each does/doesn't cover: `pnpm --filter @gofish/tests validate-python-ir` (Python IR → schema; exercises 3/4 but **NOT** the reconstruction in step 2 — a story can pass this and still fail to render) and `python3 tests/scripts/check-story-ir.py <file>` (fast single-file IR check). Reconstruction (step 2) is only exercised by the **visual** capture: `pnpm --filter @gofish/tests capture-python` — run it after a new operator/mark or it'll mask a dropped construct.
6. **Docs** (see the docs-sync note in CLAUDE.md) and **the same `datum.X`→`X` / `by` migration in Python stories**, not just JS — story `by:` strings flow to the same projection.

**pytest gotcha:** the `gofish-python` widget tests need `pnpm --filter gofish-python build:widget` first; without the bundle ~19 tests fail with `FileNotFoundError: widget.esm.js` — those are environmental, not your change.
