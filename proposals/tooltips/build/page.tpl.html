Tooltips for GoFish

A proposal for issue #1395, a request for tooltips.

  • Add .tooltip() to every mark and every operator.
  • It is sugar for one more layer over the focused mark, the same construct as .label().
  • The box floats, so the chart never moves when it opens, and its content is ordinary GoFish.
tooltip
A small box of details about one mark, shown while the pointer is on or near it.
focus
The one mark, or group of marks, the pointer currently picks.
modifier
A chained method on a mark or operator that adds something about it: .name(), .label(), and now .tooltip().
layer
One more chart drawn in the same coordinate space as the first.
floating
Drawn, but takes no room in the layout, so nothing else moves when it appears.

Every picture is a real capture of the prototype with the focused mark pinned, because the capture tool cannot hover. To try the real thing, run pnpm storybook and open the stories under "Proposals/Tooltips/". The Interactive variants respond to the mouse. The interactive line and scatter stories have clipped axes, a prototype limit listed under Findings.

  • .tooltip() works on any mark and on any operator.
  • With no argument it shows one row per field that has a single value on the mark.
  • The focus is the mark whose outline is nearest the pointer within radius pixels. Being inside a mark is distance zero.
  • The box floats. It takes no room and is not a pointer target.

  • A modifier is sugar for one more layer over the thing it is attached to.
  • .label() and .tooltip() are the same construct.
  • A tooltip differs from a label in exactly three ways: it is drawn only for the focus, its box is floating, and its default content is a table of fields instead of one text.

What .tooltip() means

The focus is a dataset of zero or one bar. pointer().snap(selectAll(...)) is the spelling already chosen in #849 (hover that picks the nearest mark within a radius). Treating an input as a dataset is the direction of #830 (an interaction grammar).

Signature

.tooltip(content?, options?) on any mark and on any operator. The content is a list or a function, so an object in first place is the options.

  • No argument: one row per field with a single value on this mark. That is every field that is constant across the mark's rows, plus each field the mark draws, shown with its drawn value (a stacked segment's summed count). This joins Vega-Lite's "data" and "encoding" contents.
  • A list of fields: order is row order. This form is plain data, so it serializes and works in Python and in the notebook widget with no Python callback.
  • A function from the rows to any mark: the content is ordinary GoFish. JavaScript only at first.
  • Options: by groups the marks by a field and makes the group the focus. radius is how near counts, in pixels. position takes the same Place family and the same chooser that labels use, so the box stays inside the chart and flips sides.

The focus

One rule: the mark whose outline is nearest the pointer within radius pixels, where being inside a mark is distance zero. A bar is picked when the pointer is on it. A small point or a thin line is picked when the pointer is near it. There is no mode to switch. Compare Plot's pointer (a 40 px maxRadius), Vega-Lite's nearest: true (which does not work on lines), and Plotly's hoverdistance.

Groups

A tooltip for a group comes from structure. There is no chart-wide mode.

  • On an operator: spread({ by: "lake", dir: "x" }).tooltip() is a tooltip for each lake's whole stack. It needs operators to be nameable (#802).
  • With by on a mark: circle(...).tooltip({ by: "year" }) groups marks that are not one node in the tree, such as the points of every series at one year. This is the shared tooltip that Plotly calls hovermode: "x unified", ECharts trigger: "axis", and Highcharts shared. Observable Plot does not have it (its issue 2003 is open).
  • The rule and the dots in the line example are two more layers over the same focus. They are not tooltip options.

Floating

The box is drawn, takes no room, and is not a pointer target. .hidden() already means "takes room, not drawn". .floating() is its counterpart. The engine has this today as a private flag, which the prototype sets by hand, so this names something that exists.

Speed

The tooltip is an ordinary subtree. Later, incremental layout (#674) re-lays-out only that subtree, and floating is what makes it a boundary, because its size never feeds back to its parent. Until then the pointer is split in two. Which mark is the focus re-runs layout. Where the pointer is does not. The default position is anchored to the mark, so nothing has to move between focus changes. Following the cursor would be one more Place strategy later.

Static files and screen readers

The same content is also written as an SVG <title> on the mark. A saved SVG and a static Python export still show the browser's own tooltip, and screen readers announce it. Vega-Lite does the same with its ARIA description. Keyboard focus and touch are not designed here. An anchored box is what makes them possible later.

Number formats

The issue's screenshot shows 11,902 and 13.0%. GoFish formats nothing today beyond String(). A tooltip value uses the same formatter as that field's axis ticks, and field("share").format(...) overrides it. Formatting needs its own short design, built on Intl.NumberFormat. This proposal only depends on it. The prototype carries its own formatters.

Approaches compared

Approach Code Makes easy Makes awkward
A, recommended. A .tooltip() modifier defined by rewrite into a layer over the focus. {{appr-a}} One call for the common case. The long form is ordinary layers anyone can edit. It needs .layer(fn) on marks, nameable operators and .floating(), none of which exist yet.
B, runner-up. Hover as an option of .label(). {{appr-b}} One construct fewer. It reuses label placement as it is. One option flips three defaults at once: content, room, and which marks.
C. No sugar, only the explicit layers. Plot's explicit form and Swift Charts' selection plus annotation work this way. {{appr-c}} Nothing new to learn. It is A's expansion. Too long for exploration. Altair's multi-series tooltip is five layers.
D, a foil. A chart-level option with a trigger mode: ECharts trigger, Plotly hovermode, Highcharts shared. {{appr-d}} A shared tooltip across series in one word. It lists modes instead of composing them, and its content is a string template.

What would change the pick: if .layer(fn) on marks turns out not to be buildable on the label machinery, B becomes more attractive, because it reuses .label() as it is.

  • The question: "I've heard that if we do method chaining and a third party is extending the methods then it will be a runtime error vs if we have a function people have to import then it will be a static error, but I'm not sure."
  • Partly right. The runtime errors come from patching a method onto marks after the fact. Chaining by itself is safe.
  • GoFish marks cannot be patched at all today. A mark is a function, and each call re-attaches a fixed private list of methods.
  • The extension point is a method that already exists by name: .layer(fn) on marks and operators, where fn takes the selection of that mark and returns a chart.

What this changes

  • api-design.md says a method that reaches outward from a node, like .label, has no function twin. This recommendation gives label and tooltip function forms, so that rule would be restated.
  • #615 (an internal API for registering modifiers) and #1291 (one table that drives every node modifier) ask for one internal table that defines each modifier once. That table is where the rewrite would live. It has no user-facing spelling.
  • #803 (make .label() build the public layered form instead of a private one) is the label half of the rewrite rule. It must keep every label render unchanged.
  • Not prototyped: .layer(fn) on a mark, operator .name(), .floating(), and pointer().snap().

What the prototype found

Finding What it means Issue
There is no way to name an operator's group. The whole-stack tooltip uses an outline of the segments as a stand-in. #802, operators cannot be named
Nearest within a radius needs a data-to-pixel map on the pointer. The prototype estimates pixel distance from the chart size. #849, nearest-mark hover
An input cannot be a chart's dataset yet. The focus is computed outside the spec. #830, an input is a dataset
Node ids change on every re-run. The focus is compared by key. #673, stable identity
Every pointer move re-runs layout unless split by hand. The prototype splits focus from position by hand. #674, incremental layout, is the long-term fix
Hover cannot be captured for visual tests. The pictures pin the focus. #672, scripted interaction in captures
pointer().dataPos() is undefined when the chart sets its own w/h. The interactive line and scatter stories size the render instead. unfiled
A layer with no marks moves the plot. 0.75 px in the closed line story. In a render-sized chart it moved the x axis by 46 px, which is why the interactive line and scatter stories have clipped axes. unfiled
Nothing sets pointer-events. A box under the cursor steals the hit and flickers. The prototype fixes it with story CSS. unfiled
A chart nested in a tooltip shares the outer chart's scale for a field of the same name. The nested chart renames count to n. unfiled
A relational mark paints under the marks it references. The box needed .zOrder(1). unfiled
filter with no match still calls the mark with an empty list. Each story adds a group after the filter. unfiled
There is no number formatting. The helpers carry their own formatters. unfiled
The box's side is picked by hand. The label chooser should pick it. This is a declared shortcut in the prototype. unfiled
