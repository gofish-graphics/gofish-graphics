4. Rules that check how a chart uses the draws

4.1 Marks per draw need a finite repeat

A step that places one mark per draw needs a finite repeat: a spread, time.sequence or table by draw, painting draws over each other without a blend, a stack in a bin, and a channel that reads draw, such as color by draw. So does a spread by p, which places one mark per level. None of these has a limit, so none has a bare-Dist form. A bare Dist in a channel always means the expected picture of its mark (section 1, addition 5).

Sorted bars stay finite. As n grows, the bars of a spread by p tend to the CCDF bar, which the ccdf mark of section 1 draws from a summary of the draws. That is a relation between two specs, not one spec at a limit.

4.2 Combining cells within one draw

Many steps combine several cells into one shape: a line across x, a polygon, a scatter of two Dist columns, or a stat computed per draw over many cells (density, contour, smoother, boxplot). The shape then shows one joint value of those cells, and which joint it shows depends on the Dist the channel reads:

  • a joint the data states, read with sample("draw"): data that arrives as draws, or one joint Dist over the cells. The shape shows that joint. No message.
  • independent marginals, read with sample("draw"): the column holds a separate Dist per cell, so the shape shows the cells as independent. That is a possible world only if the cells really are independent, which GoFish cannot know, so it gets a warning that the chart assumes independence.
  • quantile p across cells, read with quantile("p"): the shape shows the cells moving in lockstep, every cell at its own 10th percentile at once. No Dist states that, so it gets a warning that the shape is a quantile curve, not a draw. This also covers two cells of one row, which is how the ggdibbler paper's anti-example in Figure 6c is written.
  • a summary per cell, such as a line through the median of each cell's draws, is not a draw. No message.

This makes precise the check discussed with Harriet in the ggdibbler side by side tab.

4.3 Stats that pool draws

A stat whose group holds draws of several cells from several draws, such as one smoother fitted to all drawn rows, treats n draws as n times as much data. It gets a warning. The fix is to fit once per draw and then use up the draw key. This is the pooled smooth in Figure 7a of the ggdibbler paper.

4.4 Stacking draws

Two draws of one cell are two alternatives, not two parts of a sum, so a stack along the draw key adds up alternatives. Both stacked-draw charts in the ggdibbler catalog do this, which is the paper's own argument. The stacked quantity there is a count, and a count can be summed, so the CanSum rule does not catch it. The draw key has to: a stack whose children differ by the draw key is an error. A dotplot is different. Its stack runs along a bin of one cell, each dot standing for probability 1/n, and probabilities of different draws do add.

5. What the catalog changed

  • The channel reads the draws. Eight ggdibbler examples use one seed so two layers read the same draws. The earlier draft made sample a data step for that reason, since a step inside one chart's flow can't be shared. Now value.sample("draw") is fixed by the seed, the row and the draw number, so two layers that read draw k of the same rows get the same value, and each chart makes its own copies with repeat. The copies can come after steps that do not need them, such as the spread by category in 2.1.
  • Quantile levels replaced sorting the draw key. Version 1 ranked draws with field("draw").sort("value"). That ranks inside a cell only because of how today's sort happens to work, and it breaks when a cell has several rows per draw. repeat writes evenly spaced levels p, and value.quantile("p") reads each cell's quantile there, which says what it means. The earlier draft added a level column instead. This also makes rule 4.2 work on lines: version 1's rule fired on ggdist's own median line.
  • The limit is a bare Dist in a channel. The earlier draft asked for the limit with sample(data, { n: Infinity }) and a mean blend. Now rect({ h: value }) is the limit of value.draws(n), which is shorthand for a repeat and a mean blend right before the mark (section 1, addition 5). So there is no infinite draw key, and rule 4.1 only says which steps need a finite repeat.
  • Independence moved from the draw key to the Dist. The earlier draft typed the draw key as shared across cells or made per cell. Now a column of separate Dists is a set of independent marginals, and a joint is something the data states, as draws or as one joint Dist. Rule 4.2 reads it there.
  • Summaries are a way to use up draws. About 60 ggdist charts draw an interval, and none could be written by filtering ranks. They need the quantiles of the draws.
  • The slab is the density curve of the draws, not the limit of the dotplot. A dotplot reaches the slab only as the number of draws grows and the bin width shrinks together, so no bare Dist gives it. This keeps Josh's 11-04 decision that the slab is separate. It is not a new built-in mark either. The slab of section 1 is the density curve in a derive, a scatter and a ribbon, and the interval is one rect per level and a circle at the median.
  • ggdist has a second kind of mark. Its gradient interval sets opacity from the density scaled so the peak is opaque, and the Correll and Gleicher fades are flat in the middle and fade in the tails. Neither is the limit of any picture of draws. Each is a function of the distribution, drawn with an ordinary channel: the density curve or the CDF of the draws, then opacity from data. So blend stays a plain average with no rescaling option. Today GoFish lacks an opacity that varies along one region, which the catalog counts as a GoFish gap.
  • M(U(X)) and U(M(X)) are kinds of charts, not packages. A chart that reads only quantiles or summaries per cell depends only on each cell's own distribution. A chart that joins draw k of cells whose joint the data states, or summarizes each draw, depends on how cells move together. ggdist's curve_interval is the second kind. Every ggdibbler example draws from independent marginals, so in information they are all the first kind, even when they draw a line along the draw key (which rule 4.2 warns about).
  • Two levels need a second source of draws. ggdist's MCSE dots show the uncertainty of a sample itself. That needs a Dist<Dist<T>> made from a sample by resampling. repeat names its columns, so the second draw key is no longer a problem (outer and p in Catalog entry 65), but the constructor is still missing, so the catalog counts these charts as not fitting.

Still open in version 2

  • The density curve and the CDF of the draws are curves, not single values. The catalog turns them into rows with densityCurve, so a channel reads a column. The text does not yet say whether a channel can read a curve directly.
  • What a cell is for data that arrives as draws. ggdist's quantile dots of a sample (Catalog, ggdist 21 and 38) need one Dist per cell made from its rows, which the catalog writes as cellsOf and counts as a GoFish gap.
  • Band depth compares pairs of whole draws, so it is not a summary per draw (ggdist catalog entry 88).
