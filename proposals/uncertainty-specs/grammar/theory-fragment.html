This tab puts ggdist and ggdibbler inside GoFish. The claim is that neither package needs a grammar of its own: once draws are rows, every chart in either package is a GoFish flow over those rows. GoFish needs four additions, listed in section 1. This is version 2 of the claim. Version 1 was checked against every example in both packages (the Catalog tab: 96 ggdist vignette charts and 122 ggdibbler examples), and section 4 lists what that check changed. Section 5 compares real ggdist and ggdibbler renders with the GoFish spec for each.

1. What GoFish needs

A cell is one uncertain value, such as one bar's height or one map region's rate.

  1. sample(data, { n }) is a data step. It turns each distribution cell into n rows and adds two columns: draw, which says which draw a row is, and level, the row's quantile level inside its own cell (its value's CDF, a number from 0 to 1). n may be Infinity. at: "quantiles" takes evenly spaced levels instead of random draws, which is what ggdist's dotplots of a distribution do. Because it is a data step, several layers can read one sample. Data that already arrives as draws declares its draw key in the schema, as in the proposal, and gets its level from each cell's ranks.
  2. blend: "mean" on group puts every draw in one frame and averages them. This is from Blur as a limit.
  3. Summaries of the draws. A summary takes the list of draws in a group and returns one value, such as the mean or a quantile, or one curve, such as the density. The summaries are mean, median, quantile(p), min, max, the probability of a bin, and the density curve. In a channel they are methods, such as value.median(). Inside a derive, two data helpers turn them into rows: densityCurve gives the density curve as rows, and centralIntervals gives one row per interval level. Some summaries exist today. They are not special to draws, but ggdist is built on them.
  4. The draw key's type. The key records whether draws are shared across cells (draw 3 is one whole run of a model) or made per cell, and whether n is finite. Section 3 gives the rules that read it.

Everything else is GoFish as it is today.

Marks defined in GoFish

ggdist's slab, interval and line ribbon are not new built-in marks. They are ordinary user code, written below in today's GoFish, and every spec in this tab and in the Catalog uses them. Each one is a function that returns a mark. The interval returns a function of the group's rows, as .mark((rows) => ...) already allows, because each of its levels gets its own fixed thickness. ccdf is the slab with thickness P(value > v) in place of the density. gradientinterval is a variant of the slab that carries a GoFish gap.

The definitions use two data helpers. The specs can be read without them.

  • densityCurve(rows, x, { n, range, normalize }) gives the density curve of the draws as n rows { v, density, cdf }. range: [lo, hi] sets where the curve starts and ends; an end left out keeps its default. normalize: "peak" divides the density by its peak. On a sample, cdf is the sample's ECDF.
  • centralIntervals(rows, x, levels, { by }) gives one row per level { level, center, size, median }: the central interval that holds that share of the draws.

The core of each mark, without options:

// slab: the density curve of the draws, drawn as a ribbon
const slab = (x) =>
  chart()
    .flow(derive((rows) => densityCurve(rows, x)), scatter({ x: "v" }))
    .mark(ribbon({ h: "density" }));

// ccdf: like the slab, but its thickness is P(value > v), the chance the value is above v
const ccdf = (x) =>
  chart()
    .flow(derive((rows) => densityCurve(rows, x).map((r) => ({ ...r, ccdf: 1 - r.cdf }))),
          scatter({ x: "v" }))
    .mark(ribbon({ h: "ccdf" }));

// interval: one rect per central interval (the wider, the thinner), and a circle at the median
const interval = (x, levels = [0.95, 0.66]) => (rows) => {
  const ints = centralIntervals(rows, x, levels);
  return layer([
    ...ints.map((d, i) => rect({ cx: v(d.center), w: v(d.size), h: 1.5 + 2.5 * i })),
    circle({ cx: v(ints[0].median), r: 4 }),
  ]);
};

// lineribbon: at each value of along, a ribbon per central interval, and a line through the medians
const lineribbon = (y, { along, levels = [0.95, 0.8, 0.5] }) => layer([
  chart().flow(derive((rows) => centralIntervals(rows, y, levels, { by: along })),
               group({ by: "level" }), scatter({ by: along, x: along }))
    .mark(rect({ w: 0, cy: "center", h: "size" })).layer(ribbon({ fill: "level" })),
  chart().flow(derive((rows) => centralIntervals(rows, y, [0], { by: along })),
               scatter({ by: along, x: along, y: "median" }))
    .mark(line()),
]);

// slab: the density curve of the draws, as a ribbon. side "start" hangs it below the line,
// and "both" mirrors it. density holds densityCurve's options; curve(c, rows) may cut or
// rewrite the curve's rows.
const slab = (x, { dir = "x", side = "end", density = {}, curve = (c) => c, ...o } = {}) => {
  const half = (s) => chart()
    .flow(derive((rows) => curve(densityCurve(rows, x, density), rows).map((r) => ({ ...r, density: s * r.density }))),
          scatter({ [dir]: "v" }))
    .mark(ribbon({ dir, [dir === "x" ? "h" : "w"]: "density", fill: SLAB, ...o }));
  return side === "both" ? layer([half(1), half(-1)]) : half(side === "start" ? -1 : 1);
};

// interval: one rect per interval of the draws, the widest drawn first and thinnest, and a
// circle at the median. A rect sits at its interval's center, the midpoint, which is the
// median only when the distribution is symmetric (not a lognormal, a beta, or most samples).
const interval = (x, { levels = [0.95, 0.66], dir = "x", intervals = centralIntervals,
                       point = "median", fill = INK, ...o } = {}) => (rows) => {
  const [c, s, t] = dir === "x" ? ["cx", "w", "h"] : ["cy", "h", "w"];
  const ints = intervals(rows, x, levels), n = ints.length;
  return layer([
    ...ints.map((d, i) => rect({ [c]: v(d.center), [s]: v(d.size),
                                 [t]: n === 1 ? 4 : 1.5 + (2.5 * i) / (n - 1), fill, ...o })),
    ...(point ? [circle({ [c]: v(ints[0][point]), r: 4, fill })] : []),
  ]);
};

// lineribbon: at each value of along, one ribbon per central interval of the draws, and a
// line through their medians.
const lineribbon = (y, { along, levels = [0.95, 0.8, 0.5], fill = "level", stroke = INK, ...o } = {}) => layer([
  chart().flow(derive((rows) => centralIntervals(rows, y, levels, { by: along })),
               group({ by: "level" }), scatter({ by: along, x: along }))
    .mark(rect({ w: 0, cy: "center", h: "size" })).layer(ribbon({ fill, ...o })),
  chart().flow(derive((rows) => centralIntervals(rows, y, [0], { by: along })),
               scatter({ by: along, x: along, y: "median" }))
    .mark(line({ stroke, strokeWidth: 2 })),
]);

// gradientinterval: the slab divided by its peak, read as opacity over the full height.
// gap: GoFish has no opacity that varies along one region.
const gradientinterval = (x, o = {}) => slab(x, { density: { normalize: "peak" }, opacity: "alpha", ...o,
  curve: (c) => c.map((r) => ({ ...r, alpha: r.density, density: 1 })) });

// ccdf: the slab with thickness P(value > v), the chance the value is above v, instead of the
// density. ggdist starts the bar at the axis's lower limit: pass it as density: { range: [lo] }.
const ccdf = (x, o = {}) =>
  slab(x, { ...o, curve: (c) => c.map((r) => ({ ...r, density: 1 - r.cdf })) });

3. Rules the draw key's type checks

3.1 n = Infinity

An infinite draw key has no list of draws to place. A chart may use one only if every step that reads it turns the draws into something with a meaning at the limit: an average picture (blend: "mean") or a summary of the draws. A step that places one mark per draw is an error at n = Infinity, because infinitely many marks cannot be drawn. That covers spread, time.sequence or table by draw, painting without a blend, and stack in a bin. It also covers a spread by level, which places one mark per row in order of level: at n = Infinity each mark would have zero width. A channel that reads draw (such as color by draw), or a draw key that nothing uses up, is an error too.

Sorted bars do have a limit. As n grows, the bars of a spread by level tend to the CCDF bar, which the ccdf mark of section 1 draws from a summary of the draws. That is a relation between two specs, one at finite n and one that summarizes the draws. It is not one spec at n = Infinity. level itself stays legal at n = Infinity when a summary or a channel reads it, such as an opacity from level, and nothing places a mark per row.

3.2 Combining cells within one draw

Many steps combine several cells into one shape: a line across x, a polygon, a scatter of two Dist columns, or a stat computed per draw over many cells (density, contour, smoother, boxplot). The shape then shows one joint value of those cells, and which joint it shows depends on the key that ties the cells together:

  • a shared draw key shows the joint the data states. No message.
  • a per-cell draw key shows the cells as independent. That is a possible world only if the cells really are independent, which GoFish cannot know, so it gets a warning that the chart assumes independence.
  • level shows the cells as moving in lockstep: every cell at its own 10th percentile at once. The data never states that, so it gets a warning that the shape is a quantile curve, not a draw. This also covers at: "quantiles" over several cells, which is how the ggdibbler paper's anti-example in Figure 6c can be written.
  • a summary per cell, such as a line through the median of each cell's draws, is not a draw. No message.

This makes precise the check discussed with Harriet in the ggdibbler side by side tab.

3.3 Stats that pool draws

A stat whose group holds draws of several cells from several draws, such as one smoother fitted to all drawn rows, treats n draws as n times as much data. It gets a warning. The fix is to fit once per draw and then use up the draw key. This is the pooled smooth in Figure 7a of the ggdibbler paper.

3.4 Stacking draws

Two draws of one cell are two alternatives, not two parts of a sum, so a stack along the draw key adds up alternatives. Both stacked-draw charts in the ggdibbler catalog do this, which is the paper's own argument. The stacked quantity there is a count, and a count can be summed, so the CanSum rule does not catch it. The draw key's type has to: a stack whose children differ by draw is an error. A dotplot is different. Its stack runs along a bin of one cell, each dot standing for probability 1/n, and probabilities of different draws do add.

4. What the catalog changed

  • sample moved from the flow to the data. Eight ggdibbler examples use one seed so two layers read the same draws. A step inside one chart's flow can't be shared.
  • level replaced sorting the draw key. Version 1 ranked draws with field("draw").sort("value"). That ranks inside a cell only because of how today's sort happens to work, and it breaks when a cell has several rows per draw. A level column says what it means. It also makes the line rule in 3.2 work: version 1's rule fired on ggdist's own median line.
  • Summaries are a way to use up draws. About 60 ggdist charts draw an interval, and none could be written by filtering ranks. They need the quantiles of the draws.
  • The slab is the density curve of the draws, not the limit of the dotplot. A dotplot reaches the slab only as the number of draws grows and the bin width shrinks together, so no single flow at n = Infinity gives it. This keeps Josh's 11-04 decision that the slab is separate. It is not a new built-in mark either. The slab of section 1 is the density curve in a derive, a scatter and a ribbon, and the interval is one rect per level and a circle at the median.
  • ggdist has a second kind of mark. Its gradient interval sets opacity from the density scaled so the peak is opaque, and the Correll and Gleicher fades are flat in the middle and fade in the tails. Neither is the limit of any picture of draws. Each is a function of the distribution, drawn with an ordinary channel: the density curve or the CDF of the draws, then opacity from data. So blend stays a plain average with no rescaling option. Today GoFish lacks an opacity that varies along one region, which the catalog counts as a GoFish gap.
  • M(U(X)) and U(M(X)) are kinds of charts, not packages. A chart that reads only level or summaries per cell depends only on each cell's own distribution. A chart that joins cells along a shared draw key, or summarizes each draw, depends on how cells move together. ggdist's curve_interval is the second kind. Every ggdibbler example uses per-cell draws, so in information they are all the first kind, even when they draw a line along the draw key (which 3.2 warns about).
  • Two levels need a second source of draws. ggdist's MCSE dots show the uncertainty of a sample itself. That needs a Dist<Dist<T>> made from a sample by resampling, and a way to name the second draw key, since sample always writes draw and level. Both are still missing, so the catalog counts these charts as not fitting.

Still open in version 2

  • The density curve and the CDF of the draws are curves, not single values. The catalog turns them into rows with densityCurve, so a channel reads a column. The text does not yet say whether a channel can read a curve directly.
  • What sample does on a cell that is not a distribution, and what a cell is for data that arrives as draws.
  • The fixed column names draw and level clash with data (LakeHuron has its own level) and with a second draw key.
  • Thinning a sample to n quantiles, for ggdist's quantile dots of a sample.
  • Band depth compares pairs of whole draws, so it is not a summary per draw (ggdist catalog entry 88).
