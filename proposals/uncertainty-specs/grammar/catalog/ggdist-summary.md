# ggdist catalog: summary

This catalog tests the grammar in `../theory-fragment.html` against every
plotted chunk of the four vignettes installed with ggdist 3.3.3:
slabinterval, dotsinterval, lineribbon and freq-uncertainty-vis. The entries
are in `ggdist.json`, the renders in `img/`, and the R code in
`render-ggdist.R`. That file is generated by `gen-render-ggdist.py`, which
copies each chunk verbatim from `system.file("doc", package = "ggdist")`.
`build-ggdist.py` writes the JSON. It takes the R code from the render script
and holds the GoFish specs, use-ups, fit classes and notes.

To rebuild, run these from the repo root:

```sh
python3 proposals/uncertainty-specs/grammar/catalog/gen-render-ggdist.py
Rscript proposals/uncertainty-specs/grammar/catalog/render-ggdist.R
python3 proposals/uncertainty-specs/grammar/catalog/build-ggdist.py
```

## Selection

There are 97 plotted chunks: 39 in slabinterval, 29 in dotsinterval, 21 in
lineribbon and 8 in freq-uncertainty-vis. Chunks that only print a table or a
model (`priors`, `parse_dist`, `summarized_df`, `analytical_df`,
`m_ABC_summary`, `m_ABC_coefs`, `m_iris_v`) and the `eval=FALSE` chunk
`priors_fake` are not entries. The five annotated diagrams
(`slabinterval_family`, `slabinterval_components`, `dotsinterval_components`,
`dots_components`, `layout_params`) are drawn with `echo=FALSE`, but they are
plots, so they are entries.

**Merges.** There is one merge, so the catalog has 96 entries:

- `stat_lineribbon_gradient_rampbar` is merged into entry 73,
  `stat_lineribbon_gradient`. Both draw 50 nested bands colored by level and
  differ only in the color scale and the legend. Its render is
  `img/ggdist-73-stat-lineribbon-gradientb.png`.

No other pair differs only in theme, color or labels. For example,
`gradient_dodge` and `gradient_dodge_nice` differ in `fill_type`, and
`stat_lineribbon_2groups_ramp` and `..._group_order` differ in drawing order,
so they are separate entries.

**Not rendered.** None. `stat_mcse_dots` and `curve_interval` need the
`posterior` package, and `.interval = "bd-mbd"` needs `fda`. Both were
installed from CRAN for this run.

**README.** The installed package has no README (it is not in
`system.file(package = "ggdist")`), so no README examples are included.

## Version

The specs follow version 2 of the grammar (`../theory-fragment.html`):
draws made in the flow with `derive(repeat(n, "draw"))` or
`repeat(n, { level: "p" })` and read in a channel with `value.sample("draw")`
or `value.quantile("p")`, `blend: "mean"`, summaries of the draws,
independence as a property of the Dist, and a bare Dist in a channel as
shorthand for the expected picture. Each entry keeps
its version 1 class in `v1_fit`. Each entry also has a `verdict` under rules
4.1 to 4.4. `v1-fits.json` holds the version 1 classes of both catalogs.

Summary spelling. A summary takes the list of draws in a group and returns
one value, such as the mean or a quantile, or one curve, such as the density.
The fragment lists the summaries but does not spell them. In a channel the
specs write them as methods on a Dist expression or a field: `x.mean()`,
`x.median()`, `x.quantile(p)`, `x.min()`, `x.max()`, and `x.probability()`
inside a cell made by binning `x`. Slabs, intervals and line ribbons are not
built-in marks (Josh, 11-04). The specs call `slab`, `interval`,
`lineribbon`, `gradientinterval` and `ccdf`, which are ordinary user code of a few
lines each, defined in section 1 of `../theory-fragment.html` and copied in
the prelude below. On a Dist cell a summary
is exact. On rows of a sample, the density curve is a kernel estimate.
`as("dist")` reads a column of Dist cells as a Dist expression.

Every verdict is ok. The only joins across cells are the shared-draw
spaghetti (69, 81, 82, 85), which rule 4.2 allows because the schema declares
the draws shared, and median lines, which are summaries. No spec stacks draws of
one cell as parts of a sum.

Movement from version 1 to version 2:

| v1 → v2                     | entries | which |
| --------------------------- | ------: | ----- |
| `fits` → `fits`             | 32 | |
| `gofish-gap` → `gofish-gap` | 51 | |
| `does-not-fit` → `gofish-gap` | 10 | 01, 18, 19, 24, 25, 26, 92 (gradients and fades); 83, 84, 87 (curvewise mhd) |
| `does-not-fit` → `does-not-fit` | 3 | 65, 66 (MCSE dots); 88 (band depth) |

No entry moved to a worse class. Many entries kept their class but changed
how they use up the draws. In version 1, about 60 slabs, intervals and bands
came from a derive that computed the distribution by hand. In version 2 they
come from summaries of the draws, which is a row of the table.

How the draw key is used up:

- **Summaries per cell.** About 50 entries: every slab (the density curve),
  interval, point and lineribbon band (quantiles and the median). 15 reads
  the pmf at 0 to 20 with `densityCurve`. The CCDF bars (16, 17, 93 and part of 01)
  use the CDF of the draws, through the `ccdf` mark; on a sample (16, 17)
  that is the sample's ECDF.
- **Partition by a bin, then stack.** About 30 dotplot entries. Over a
  sample the rows are the draws. Over a Dist, `repeat(n, { level: "p" })`
  and `x.quantile("p")` make the dots (37, 40, 41, 60 to 63, 94, and part of
  01). 21 and 38 take quantile dots of a sample: `cellsOf` makes one Dist per
  cell from its rows, then the same `repeat` and `quantile("p")`.
- **A spread by `p`.** No catalog spec spreads by `p`. It needs a finite
  `repeat` (rule 4.1). Sorted bars tend to the `ccdf` picture as n grows,
  which is a second spec.
- **`blend: "mean"`.** 22, the CCDF fade, over all 1000 rows of each cell.
  Its shorthand would be `rect({ h: value })` over `cellsOf`, whose limit is
  exactly this average.
- **The plain overlay.** 69, 81, 82 and 85 draw shared whole-curve draws with
  `group({ by: ".draw" })`.
- **A summary per draw.** 83, 84 and 87 score each whole curve and keep the
  deepest.
- **A dot layout over the rows.** 45, 46, 48 to 50, 58 and 59.

## Prelude used by the specs

The specs use a few names that they do not define. They are plain JavaScript
over today's GoFish plus the version 2 additions. They add no other syntax.

```js
const INK = "black";
const SLAB = "gray65";

// Data that arrives as draws has no draw column. withDraw adds a row index so
// the schema can declare it: { schema: { value: { draws: "draw" } } }.
const withDraw = (rows) => rows.map((r, i) => ({ ...r, draw: i }));

// cellsOf(rows, { by, draws }) (21, 38; a GoFish gap): one row per value of
// by, whose column draws holds the empirical Dist of that cell's rows.

// Read a column of Dist cells as a Dist expression.
// as("dist").median(), as("dist").bin(...), ...

// Two data helpers, used inside derive(...) like normalize() and repeat().
// x is a column name (plain values or Dist cells) or a Dist expression. Each
// helper takes one distribution from the rows it is given: their mixture,
// or the empirical distribution of plain values (elaborations.md, foldDist).
// Each output row keeps the columns that every input row shares, such as
// the group's keys, so fill: "subgroup" still reads.

// densityCurve(rows, x, { n = 121, range, normalize } = {}): the density
// curve of the draws at n evenly spaced values. One row per value:
// { v, density, cdf }. range defaults to the distribution's display range
// (support()); an end left out keeps its default, so range: [0] starts the
// curve at 0. normalize: "peak" divides the density by its peak. On a
// sample the density is a Gaussian kernel estimate (Silverman bandwidth)
// and cdf is the sample's ECDF.

// centralIntervals(rows, x, levels, { by } = {}): the equal-tailed central
// interval of the draws at each level p, from Q((1 - p) / 2) to
// Q((1 + p) / 2). One row per level: { level, center, size, median }, where
// center is the interval's midpoint and size its width. center equals the
// median only for a symmetric distribution. With by (a field or a list of
// fields), one row per level and per value of by, with the by columns.

// The marks, as in section 1 of ../theory-fragment.html. The interval's mark
// is a function of the group's rows, as .mark((rows) => ...) allows.
// slab: the density curve of the draws, as a ribbon. side "start" hangs it below the line,
// and "both" mirrors it. density holds densityCurve's options; curve(c, rows) may cut or
// rewrite the curve's rows.
const slab = (x, { dir = "x", side = "end", density = {}, curve = (c) => c, ...o } = {}) => {
  const half = (s) => chart()
    .flow(derive((rows) => curve(densityCurve(rows, x, density), rows).map((r) => ({ ...r, density: s * r.density }))),
          scatter({ [dir]: "v" }))
    .mark(ribbon({ dir, [dir === "x" ? "h" : "w"]: "density", fill: SLAB, ...o }));
  return side === "both" ? layer([half(1), half(-1)]) : half(side === "start" ? -1 : 1);
};

// interval: one rect per interval of the draws, the widest drawn first and thinnest, and a
// circle at the median. A rect sits at its interval's center, the midpoint, which is the
// median only when the distribution is symmetric (not a lognormal, a beta, or most samples).
const interval = (x, { levels = [0.95, 0.66], dir = "x", intervals = centralIntervals,
                       point = "median", fill = INK, ...o } = {}) => (rows) => {
  const [c, s, t] = dir === "x" ? ["cx", "w", "h"] : ["cy", "h", "w"];
  const ints = intervals(rows, x, levels), n = ints.length;
  return layer([
    ...ints.map((d, i) => rect({ [c]: v(d.center), [s]: v(d.size),
                                 [t]: n === 1 ? 4 : 1.5 + (2.5 * i) / (n - 1), fill, ...o })),
    ...(point ? [circle({ [c]: v(ints[0][point]), r: 4, fill })] : []),
  ]);
};

// lineribbon: at each value of along, one ribbon per central interval of the draws, and a
// line through their medians.
const lineribbon = (y, { along, levels = [0.95, 0.8, 0.5], fill = "level", stroke = INK, ...o } = {}) => layer([
  chart().flow(derive((rows) => centralIntervals(rows, y, levels, { by: along })),
               group({ by: "level" }), scatter({ by: along, x: along }))
    .mark(rect({ w: 0, cy: "center", h: "size" })).layer(ribbon({ fill, ...o })),
  chart().flow(derive((rows) => centralIntervals(rows, y, [0], { by: along })),
               scatter({ by: along, x: along, y: "median" }))
    .mark(line({ stroke, strokeWidth: 2 })),
]);

// gradientinterval: the slab divided by its peak, read as opacity over the full height.
// gap: GoFish has no opacity that varies along one region.
const gradientinterval = (x, o = {}) => slab(x, { density: { normalize: "peak" }, opacity: "alpha", ...o,
  curve: (c) => c.map((r) => ({ ...r, alpha: r.density, density: 1 })) });

// ccdf: the slab with thickness P(value > v), the chance the value is above v, instead of the
// density. ggdist starts the bar at the axis's lower limit: pass it as density: { range: [lo] }.
const ccdf = (x, o = {}) =>
  slab(x, { ...o, curve: (c) => c.map((r) => ({ ...r, density: 1 - r.cdf })) });

// keepDeepest({ by, along, value, share }) (83, 84, 87): a derive that scores
// each draw (by) by the mean over along of its depth min(F, 1 - F), where F
// is the CDF of the draws at that value of along, read at the draw's value.
// It keeps the deepest share of draws.
```

A gap is a `// gap:` comment at the place it occurs. A gap that belongs to
a mark sits with its definition: the gradient interval's opacity along one
region is on `gradientinterval`. Cut slabs pass a `curve` that filters the
curve's rows, so their ends are as fine as the curve's grid. The mode and
the highest-density interval (30, 31, 61) are written as
`highestDensityIntervals(rows, x, levels)` and `x.mode()`, the calls they
would most likely be, with a gap comment, because version 2 does not list
them. `interval(x, { intervals: highestDensityIntervals, point: "mode" })`
draws them. Bin widths for dotplots are chosen by hand, and each `Bin.step` says
so: ggdist picks the width so the tallest stack fits.

Data names are the R data frames in camelCase (`df`, `distDf`, `priors`,
`abccDf`, `mtcarsBoot` and so on). They have the same columns as in R. Where
R builds a `dist_*` column, the spec builds the matching `dist.*` channel.
`dist.beta`, `dist.studentT`, `dist.poisson` and `dist.lognormal` are taken to
be families of the proposal's `dist` namespace.

## does-not-fit (3)

- **65, `stat_mcse_dots` blur.** ggdist blurs each dot sideways by its
  quantile's Monte Carlo standard error, after binning. That is the blur
  channel the limits tab rules out, so ggdist's own picture has no draw
  spelling. Section 5 says the honest version needs a `Dist<Dist>` made from
  a sample by resampling. Version 2 names no such constructor. The two
  draw keys are no longer a problem: `repeat` names its columns, so the spec
  writes `repeat(200, "outer")` and `repeat(100, { level: "p" })` and reads
  `boot.sample("outer").quantile("p")`. Only the constructor is missing.
- **66, `stat_mcse_dots(blur = "interval")`.** Each dot's interval is a pair
  of quantiles across the outer draws, grouped by the inner level. It
  needs the same constructor as 65.
- **88, `curve_interval(.interval = "bd-mbd")`.** Band depth is the share of
  pairs of other curves whose band contains a curve at every x. That needs
  every pair of draws at once, so it is not a summary per draw. The table's
  "summary per draw" row covers mhd (83, 84, 87), which is a mean over x of
  `min(F, 1 - F)`, with F the CDF of the draws at each x.

## gofish-gap (61), by gap

- **Opacity that varies along one region (01, 18, 19, 24, 25, 26, 92).** These
  are the gradient intervals and the Correll and Helske fades. In version 2
  each one is the density curve or the CDF of the draws, read as opacity. Today GoFish's opacity
  is one number per mark.
- **A summary whose result a later step reads (83, 84, 87).** Curvewise mhd
  bands score each whole draw, filter on the score, then take the min and
  max of the kept draws. The score has to feed the filter, which today
  needs a derive (`keepDeepest`). Because it is a derive, a checker cannot
  see that it keeps whole draws.
- **Dot layouts (about 30 entries).** These are 20, 21, 37, 38, 40 to 64
  except 49's swarm panel, 67, 68 and 94. GoFish has `Bin.step`, `partition`
  and `stack`. It does not have:
  - Dot-density (Wilkinson) binning.
  - A bin width taken from the axis scale, so the dots touch and the tallest
    stack fits. ggdist's main dots feature depends on it (54 to 57).
  - The hex, weave and bar layouts (45 to 50, 58, 61, 63).
  - `overflow = "compress"` (56).
  - Kernel smoothing of a discrete position (59).
  - Side as data, `scale_side_mirrored` (37, 67, 68).
  - A shape channel (53).

  The swarm layout is `Overlap.separate`, which exists.
- **Origin alignment in a layer (04 to 07, 24, 26, 34, 37, 38, 39, 64, 91).**
  A slab on side start or both, or dots below the line, need the interval
  placed on the slab's zero line. A layer aligns boxes, not origins.
  elaborations.md found the same gap. Every `stat_eye` hits it.
- **Color ramps (27, 32, 33, 36, 78, 79, 96).** These are `fill_ramp` and
  `color_ramp`, a color scale on one field lightened by a second field, and a
  fill or outline that changes along one ribbon.
- **The mode and the HDI or HDCI (30, 31, 61).** These are general aggregates
  that version 2's list of summaries does not include.
- **Annotation brackets (02, 40, 41, 42).** These are segments with flat
  ends, and `coord_fixed` in 42.
- **Others.** 12 needs a log scale, and the density curve would need to know
  the axis transform. The subguides (10, 60) are a small axis inside each
  slab. 10 needs a truncated Dist, and 68 needs a transformed Dist. 54 to 56
  need a wrapped facet on one key. 31 maps a linetype from a field.

## Where the version 2 text is wrong or incomplete

1. **Quantile dots of a sample need a Dist per cell.** ggdist's
   `stat_dots(quantiles = 50)` on 1000 rows (21, 38) thins a sample to 50
   quantiles. `quantile("p")` reads a Dist, so the specs first make one
   empirical Dist per cell with `cellsOf`, a GoFish gap. (Changed in round 7:
   the earlier draft filtered on `level`, which had to know the row count.)
2. **The cell of data that arrives as draws is not defined.** In `df` (16, 17,
   21, 22, 38) the 1000 rows of each group and subgroup are one cell, but
   nothing in the schema says which columns name the cell. The data also has
   no draw column, so the specs still need `withDraw`.
3. **Fixed column names collided.** Resolved in round 7: `repeat` names
   the columns it writes, so two levels of draws (65, 66) get two keys, and
   data with its own `level` column (ggdibbler 60, 61) no longer clashes.
4. **"A summary per draw" covers mhd but not band depth.** mhd and modified
   band depth are means over x of a function of each value's CDF among the draws. Band depth (88)
   compares pairs of whole draws.
5. **"Not a new step" for MCSE.** With item 3 resolved, a `Dist<Dist>`
   constructor alone would make 65 and 66 writable.
6. **The density curve is a curve.** The fragment lists "the density"
   beside one-number summaries. A slab reads it at every position, and a
   gradient reads it as opacity along the slab. The fragment does not say how
   a channel reads a curve. The slab mark turns it into rows with
   `densityCurve` in a derive, so the channel reads a column.
7. **The gradient and fade marks need one more GoFish piece.** The fragment
   names the gap (opacity along one region) correctly. Fades also divide
   the opacity by its peak, not only the thickness, so that the plateau is
   opaque. That is arithmetic on the curve's rows, in the slab's `curve`.
8. **The CCDF bar needs an anchor.** It must run from a fixed point at or
   below the support (93). ggdist uses the axis's lower limit; the specs pass
   it as the curve's range, `density: { range: [lo] }`. A bar from 0 is wrong
   when the distribution crosses 0.
9. **A spread by `p` has no limit.** Version 2 first allowed a spread by
   level at n = Infinity as the CCDF bar. Rule 4.1 now says it needs a finite
   `repeat`, like a spread by `draw`, and the CCDF bar is the `ccdf` mark. Sorted bars tend to it as n grows, which is a
   relation between two specs.
